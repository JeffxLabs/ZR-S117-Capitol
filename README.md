# S117 Capitol War data

A community-maintained archive and dashboard for *Z Route: Redemption* Capitol War rankings. The repository captures in-game leaderboard data, turns it into reusable files, and publishes an interactive static site.

**[Open the dashboard](https://jeffxlabs.github.io/ZR-S117-Capitol/)** · [Pipeline details](pipeline/README.md)

## How the data is gathered

The capture pipeline controls the game in BlueStacks Air on macOS using Android Debug Bridge (ADB). It navigates to the rankings, scrolls through overlapping screens, and runs Apple's Vision OCR on screenshots. Multiple readings help resolve uncertain rows; a repair pass revisits missing, conflicting, or out-of-order ranks. The cleaner normalizes OCR output and applies corrections from `data/name_overrides.json` and `data/alliance_overrides.json`.

The pipeline checks capture quality, rank continuity, and point ordering before publishing. It saves failed runs to a local staging directory instead of updating the site, unless explicitly overridden. OCR and identity matching are imperfect: review `capture_qa.json`, suggested matches, and archived screenshots before relying on or publishing the results. Optional early screenshots can supply a safe prefix of rankings when the main capture is taken later.

## How the site works

`index.html` is a client-side dashboard; GitHub Pages serves it and the data as static files, with no application server or build step. It loads `events/manifest.js` and the event `event_data.js` bundles, allowing the dashboard to work when opened locally as well as on Pages. The per-event JSON and CSV files are available for reuse and downloads. The dashboard provides event selection, rankings, alliance views, search, and cross-event trends; `events/aliases.js` supplies manual identity links and `events/i18n.js` supplies translations.

- `events/manifest.json` and `manifest.js`: event registry, generated by the pipeline.
- `events/<event-id>/event.json`, `rankings.json`, `alliances.json`: event metadata and dashboard data; CSV exports and `event_data.js` are generated alongside them.
- `capture_rankings.json`, `capture_qa.json`, `capture.json`, and `screenshots/`: capture records, quality checks, provenance, and archived evidence where available.
- `data/`: correction rules and legacy exports pointing to the newest event.
- `pipeline/`: capture, OCR, cleaning, validation, and publication code.

## Run or update a capture

Live capture requires macOS, BlueStacks Air with the game running, Python 3, ADB (`brew install android-platform-tools`), and the Swift compiler from Xcode Command Line Tools. The OCR worker uses Apple's Vision framework. Verify the emulator is visible with `adb devices`; see the [pipeline guide](pipeline/README.md) for connection and navigation troubleshooting.

From the repository root, for example:

```sh
python3 pipeline/run_pipeline.py --date YYYY-MM-DD --opponent 119 --home-role defending --no-apparatchik --no-upload
```

The opponent and role can normally be detected from the Conquest screen; supply them when needed. `--no-apparatchik` skips this installation's optional Apparatchik integration, and `--no-upload` prevents the pipeline from automatically committing and pushing. Without those flags it may pause/resume monitoring, update its whitelist, and commit and push event files to `origin/main`. Review the output and generated QA report, then commit and push the intended changes. Use `--help` for the full set of options.

To reprocess an existing capture without the emulator, use its actual date, opponent, role, and capture file:

```sh
python3 pipeline/run_pipeline.py --date YYYY-MM-DD --opponent 119 --home-role defending \
  --from-file events/<event-id>/capture_rankings.json --no-apparatchik --no-upload
```

The pipeline regenerates the event files and manifests; it updates the legacy `data/` exports only for the newest event. `--incremental` stores a scan for reference without adding it to the dashboard. See the [pipeline guide](pipeline/README.md) for early screenshots, repair, staging, and correction workflows. Run the offline tests with:

```sh
cd pipeline && python3 -m unittest discover -s tests -v
```

## Set up a similar archive

Fork or clone this repository, configure GitHub Pages to publish from your chosen branch's root, and push the static files. For another server, pass `--home` when running the pipeline and provide the correct matchup; the dashboard branding, default assumptions, corrections, aliases, and existing event history are S117-specific and should be reviewed or changed for your archive. Capture automation also assumes this game's current screens and emulator layout, so navigation or OCR may need adjustment if either changes. Test locally and review generated data before enabling automatic uploads.
